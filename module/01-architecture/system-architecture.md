# System Architecture

## Backend Pattern

Backend dùng layered architecture:

```text
HTTP request
  -> route
  -> controller
  -> service
  -> repository
  -> Prisma
  -> MySQL
```

| Layer | Nhiệm vụ | Không nên làm |
| --- | --- | --- |
| Route | Khai báo endpoint và middleware | Business logic |
| Controller | Validate input, gọi service, trả response | Query Prisma trực tiếp |
| Service | Business rules, state transitions, formatting | SQL/Prisma chi tiết |
| Repository | Prisma queries, transaction, DB include/select | UI/business decisions |
| Middleware | Auth, admin guard, sanitize, rate limit, error handling | Module-specific logic |

Manual dependency injection nằm ở `backend/src/container.ts`.

## Frontend Pattern

Frontend là multi-page Vite app, mỗi HTML page load module JS riêng.

| Page group | Pattern |
| --- | --- |
| Storefront | DOMContentLoaded -> fetch API -> render HTML -> bind events |
| Cart guest | Lưu vào `localStorage.maverik_cart` |
| Cart logged-in | Gọi `/api/v1/cart` với Bearer token |
| Admin | `requireAdminAccess()` -> fetch admin API -> render cards/tables/charts |

## Data Flow Examples

### Login

```text
login.js
  -> POST /api/v1/auth/login
  -> AuthController.login
  -> AuthService.login
  -> UserRepository.findByEmail
  -> bcrypt.compare
  -> JWT
  -> localStorage.authToken + localStorage.user
```

### Place Order

```text
checkout.js
  -> POST /api/v1/orders
  -> authMiddleware
  -> OrderController.placeOrder
  -> OrderService.placeOrder
  -> OrderRepository.createOrderAtomic
  -> SELECT ... FOR UPDATE
  -> create Order/OrderDetail/Payment
  -> decrement stock
  -> clear cart
```

### Admin Revenue

```text
admin-revenue.js
  -> GET /api/v1/admin/revenue
  -> authMiddleware + requireAdmin
  -> AdminController.getRevenue
  -> AdminReportService.getRevenueByPeriod
  -> AdminRepository revenue queries
  -> Chart.js render/export UI
```

## Auth And Authorization

- JWT is generated by `AuthService`.
- Protected routes use `authMiddleware`.
- Admin routes use `authMiddleware + requireAdmin`.
- `authMiddleware` verifies JWT, checks user still exists, and attaches `req.userId` and `req.userRole`.
- `requireAdmin` allows only `ADMIN` and `SUPER_ADMIN`.
- Frontend admin guard is UX only; backend middleware is the real protection.

## Response And Error Conventions

- Use `sendSuccess`, `sendError`, `APIError`, and `catchAsync`.
- Do not expose `passwordHash`.
- Convert Prisma `Decimal` to `number` or formatted string before frontend math.
- Keep Zod validation close to controller boundaries.

## Current Architecture Notes

- Order/payment logic has become more current than older archived docs.
- Revenue reporting currently treats `DELIVERED` and `COMPLETED` orders as realized revenue and uses `updatedAt` for date range reporting.
- Frontend API base is partly centralized in `api-config.js`, but older files still duplicate local `getApiBase()`.
